# ADR-0008：前端使用 Ant Design 與 TanStack Query

- 狀態：Accepted
- 日期：2026-10-14

## 背景

[ADR-0003](0003-frontend-react-vite-plus.md) 決定了 React 與 Vite+，把元件庫與資料請求的選擇留到實作零件頁面時。M2 需要資料表格、搜尋、篩選選單、分頁與提示框。

## 決策

- 介面元件：Ant Design 6。
- 伺服器資料的取得與快取：TanStack Query 5。
- API 型別：用 openapi-typescript 從後端的 OpenAPI 文件產生。
- 路由與全域狀態管理：暫不引入。

## 理由

選 Ant Design：

- 平台是以表格與表單為主的內部工具，這正是它的主要用途。表格內建伺服器端分頁、排序與固定欄位，M2 與 M3 需要的元件都有現成的。
- 內建繁體中文語系。
- 元件開箱即用，不需要另外學 CSS 框架或自己組合樣式。開發者不熟前端，這點比客製化彈性重要。
- 同一個團隊有 AI 對話介面的元件庫 Ant Design X，日後做 AI 功能時可以沿用同一套外觀。

選 TanStack Query：

- 載入中、錯誤、快取、換頁時保留舊資料這些狀態都由它處理，不需要在每個元件裡用 `useEffect` 重寫一次。
- 與元件庫無關，只負責資料。

產生 API 型別：

- 後端改了回應格式而前端沒跟上時，型別檢查會直接報錯。

暫不引入路由與狀態管理：

- 目前只有一個頁面。畫面上的狀態（選了哪個類型、搜尋什麼）用 React 內建的 `useState` 就夠。
- 出現第二個頁面時加入路由。屆時把類型與搜尋條件放進網址，讓連結可以分享。

## 放棄的選項

- shadcn/ui 加 Tailwind CSS：客製化彈性最高，AI 對話介面的現成元件也多。但元件要複製進專案自己維護，表格的分頁與排序要自己組合，對不熟前端的開發者負擔較大。
- MUI：能力相近。資料表格的進階功能在付費版。
- 自己寫 `fetch` 加 `useEffect`：少一個依賴，但每個頁面都要重寫載入與錯誤處理。

## 影響

- 打包後的 JavaScript 約 1 MB（壓縮前）。平台只在內網使用，可以接受。日後頁面變多時依頁面拆分。
- openapi-typescript 7 要求 TypeScript 5，與專案的 TypeScript 6 不相容，所以不列為專案依賴，由 `task gen-api` 透過 `npx` 執行固定版本。
- 零件資料列的欄位隨類型不同，無法產生固定型別，在前端是以欄位名稱為 key 的物件。
