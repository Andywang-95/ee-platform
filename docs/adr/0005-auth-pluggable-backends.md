# ADR-0005：登入方式可抽換，權限使用 Django 內建機制

- 狀態：Accepted
- 日期：2026-10-13
- 取代：先前自建五張權限資料表、不使用 Django User 的設計

## 背景

- 公司使用者以 Windows 帳號登入電腦，期望開啟平台時自動辨識身分，不再登入一次。
- 開發在 Mac 上進行，沒有 AD。
- MVP 的權限需求只有一項：指定人員可以編輯零件。

## 決策

登入：

- 用 Django 的認證後端機制，由環境變數切換。
- 開發環境用本地帳號。
- 公司環境的目標是無感登入：由反向代理完成 Windows 整合驗證，Django 以 `RemoteUserBackend` 接收使用者名稱。
- 無感登入的條件無法滿足時，改用 LDAP 驗證的帳密表單。

權限：

- 使用 Django 內建的 User、Group、Permission。
- MVP 在 Django Admin 以個人為單位指派權限。
- 每個請求即時檢查權限。

## 理由

- 登入方式換了，權限程式碼完全不用動，開發環境與公司環境可以用同一套邏輯。
- 內建機制已涵蓋「使用者、角色、權限」的模型，並附帶管理介面。
- 即時檢查權限，變更後立刻生效，不會有 session 中殘留舊權限的問題。

## 放棄的選項

- 自建 permission、role、principal 等資料表：功能與 Django 內建的重複，還要自己做管理介面。
- 登入時把權限存進 session、之後不再查詢：權限被收回後要等使用者重新登入才生效。
- MVP 就做 AD 群組對應：目前只需要指定少數人，等人數變多再加。

## 影響

無感登入的具體做法取決於部署主機，細節見 [domains/auth.md](../domains/auth.md)。
